# 用计划面板（给助手看）

工作区里的 `todolist.json` 是用户的项目计划，DSH 右栏的「项目计划」面板就是它的界面。你用 `todolist` 工具读写它——**不要**用 write/edit 之类的工具直接改这个文件（校验严格，手改容易写坏；一旦坏了一行，面板上所有操作都会被拒绝）。

## 先记住它是什么

它是**一块你和用户共用的白板**，不是任务队列，也不是提醒器：它不排期、不催人、不会因为某条事项到点就让你开工。你维护它，是为了让用户和你自己在下一次会话里还能看到「现在处于哪个阶段」，而不是为了让面板热闹。

所以：**看到计划里有未完成的事项，不等于要现在做它们。** 只有用户当下让你做的事才做；计划只用来对齐状态和记录进展。

## 先确认这个会话有没有打开它

「计划」是一个**按会话**的开关（输入框上方的胶囊旁边），默认关闭。

- **开着**：你的系统提示里会有一段「项目计划面板（本会话已启用）」，`todolist` 可用。
- **关着**：工具会报「本会话没有启用计划面板」。这时不要反复重试，提醒用户在输入框上方打开开关即可。
- **子对话**：没有开关，一律视为关闭。工具会报「这是子对话……回报给主对话」。这种情况按它说的做：把要改的事写进结论，交给主对话。

## 分工

- **用户**只改一位：完成 / 未完成（面板左侧圆点）。
- **你**负责「进行中」（可以多项）和「下一步」（一个指针）。用户说「我在做 X」「X 是下一步」时，由你写进文件。

这个分工是刻意的：面板上不再有第二个能表达「正在做」的控件。

## 什么时候动它

- **用户明确要求**（加一条、删掉、改标题、调顺序、设下一步、标进行中）→ 直接调工具，不要反问。
- **一轮工作有实质进展**：开始做（`next` 或 `in_progress`）、做完（`completed`）、发现新任务（`add`）→ 顺手更新，不用先问。
- **与计划无关**的闲聊、一次性问答 → 不要动；也不要为了"显得在干活"而频繁改状态。

## 先读再写

调 `{"action":"read"}` 拿 id 和当前 rev。不要猜 id，也不要凭上一轮的记忆写。写入带 rev 冲突检测，文件在读取之后被别人改过会被拒绝（`stale`），那时重读再写。

## 状态语义

| 值 | 含义 | 谁写 |
|---|---|---|
| `pending` | 待办 | 两边 |
| `in_progress` | 进行中（可多项并行） | 你 |
| `completed` | 已完成 | 用户勾选，或你 |

- 完成一件：`status` = `completed`；如果它正是「下一步」，指针会自动清空。
- 开始做一件：`next` 指过去（面板显示成「下一步」）；同时推进多件：各自 `status` = `in_progress`。
- 「待前序」是推导出来的，不是状态：`after` 里还有未完成项时自动显示，且只在 `pending` 行上显示。
- 已完成的不能再设为 `next`，会被拒绝（先改回未完成）。

## 写什么

- 标题只写「做什么」，一句话。不要写状态、不要写「第 N 步」、不要复述上下文。
- 新事项挂到对应阶段的 `groupId` 下；子任务用 `addChild`（子项只有标题和状态，没有截止日期/备注/再嵌套）。
- 一次只改一件事，不要整份重写文件。
- 阶段是项目结构，别为一次性任务开新阶段；空阶段比没有阶段更糟。

## 回复用户时

如果这一轮改了计划，用一句话说明改了什么（例如「把 X 标成进行中，下一步设为 Y」），不要重复整份计划。

## 出错时

| 现象 | 处理 |
|---|---|
| `stale: 文件自上次读取后已变化` | 重读再写，别重试同一份旧数据 |
| 面板提示「计划文件有问题」 | 让用户点面板上的「移除坏项」，或先用 `repair`；不要手改 JSON 去凑 |
| `拿不到会话工作区` | 工具解析不到工作目录，不要反复重试，直接告诉用户 |
| `找不到事项 "xxx"` | id 过期了，重新 `read` |
| `invalid arguments: ...` | 参数写错了，按提示改（`action` 必须在枚举里，不要多传字段） |

## 工具速查

```text
todolist {"action":"read"}                                                读计划（带 id、状态、依赖、下一步）
todolist {"action":"addGroup","title":"…","mode":"sequence"|"parallel"|"free"} 加阶段
todolist {"action":"add","title":"…","groupId":"m2","after":["m1a"],"due":"2026-12-01"} 加事项（可带依赖与截止日期）
todolist {"action":"addChild","parentId":"m2a","title":"…"}               加子项
todolist {"action":"status","id":"m2a","status":"in_progress"}
todolist {"action":"next","id":"m2a"}                                     设为下一步（id 传 null 清空）
todolist {"action":"note","id":"m2a","note":"…"}                          写/清备注
todolist {"action":"settings","style":"vivid"|"md3"|"paper"|"calm"}       外观默认 vivid，可切四档（md3 为 Material Design）
todolist {"action":"rename"|"due"|"remove"|"move"|"reorder"|"reorderGroups"|"open"|"create", …}
```

完整操作列表与文件格式见仓库的 `SPEC.md`。
